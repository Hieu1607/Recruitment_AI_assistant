## Spacing Scale

Declared values (multiples of 4 — project base grid confirmed in globals.css):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gap, dot indicator spacing |
| sm | 8px | Intra-row padding, badge gap, inline status spacing |
| md | 16px | Panel content padding, compose field gaps |
| lg | 24px | Column header padding, section breaks |
| xl | 32px | Panel vertical rhythm between major sections |
| 2xl | 48px | Empty state vertical centering offset |
| 3xl | 64px | Page-level breathing room (top of column) |

Exceptions:
- Folder sidebar row height: 40px (10 × 4 — touch-friendly at hairline density)
- Message list row height: 72px (18 × 4 — enough for three lines: name + subject + preview)
- Detail panel minimum width: 480px; collapses to hidden on viewport < 1100px

## Layout Contract

### 3-Column Structure

The entire `/outreach` route renders a full-height, full-width 3-column layout that fills the AppShell content area (no centered max-width wrapper — mirrors email-client convention).

```
[ Folder Sidebar | Message List | Detail Panel ]
  200px fixed      320px fixed    flex-1 (min 480px)
```

Column borders: 1px solid `var(--hairline)` between each column.
Background: all three columns share `var(--bg)`. Detail panel header uses `var(--bg-elevated)` for the subject/actions strip.

Primary focal point: detail panel subject header — Fraunces 16px/600 on the elevated header strip draws the eye to the selected message content.

**Folder Sidebar (200px)**
- Header: "Outreach" label in `font-display` 14px weight 600
- "+ New message" button: full-width, `primary` variant, `sm` size, pinned at top below header (8px gap)
- Folder list: 4 items — All, Not sent, Sent, Failed
  - Active folder: `var(--accent)` left bar (3px wide) + `var(--hairline)` fill on row
  - Inactive: ghost row, `var(--fg-muted)` label
  - Count badge: `neutral` variant (for All), `warning` variant (for Not sent), `success` variant (for Sent), `danger` variant (for Failed) — `sm` size, `dot: false`
  - Row padding: 8px horizontal, 8px vertical
- Bottom: candidate filter label + combobox for `candidate_profile_id` filter
  - Combobox uses Radix Select primitive, hairline border, 13px Geist

**Message List (320px)**
- Header row: folder title in Geist 13px weight 600 + total count in `fg-muted`
- Each row is 72px tall, `border-b border-hairline`, `hover:bg-[var(--hairline)]` (120ms ease-out)
- Row layout (padding 12px horizontal, 16px vertical):
  - Line 1: candidate name — Geist 14px weight 600 `var(--fg)` + StatusBadge right-aligned
  - Line 2: subject — Geist 13px weight 400 `var(--fg)` (truncate 1 line)
  - Line 3: body preview — Geist 12px `var(--fg-muted)` (truncate 1 line) + relative timestamp right-aligned
- Selected row: `var(--hairline-strong)` background + `var(--accent)` left bar (3px)
- Empty state: see Copywriting Contract section
- Skeleton: 6 rows, each with shimmer name (100px) + badge (48px) + two text lines

**Detail Panel (flex-1, min 480px)**
- Empty state (no message selected): centered EmptyState component
- Loaded state — two zones:
  - Header strip (64px, `var(--bg-elevated)`, `border-b border-hairline`):
    - Subject in `font-display` 16px weight 600 (truncate overflow)
    - Right-aligned action row: "Mark as sent" Button (`secondary` sm) | "Delete" Button (`danger` sm)
    - "Mark as sent" is hidden when `sent_status === "sent"` or `=== "failed"`
  - Body area (scrollable, `padding: 24px`):
    - Metadata strip: candidate name (`font-display` 14px weight 600) + `content_source` badge (`neutral` size `sm`) + `created_at` relative time + `sent_at` line (conditionally shown when status = sent)
    - Separator: `border-b border-hairline` + 16px gap below
    - Body textarea: Geist 14px weight 400, `line-height: 1.6`, borderless, full-width, auto-expand, `var(--fg)` text, `var(--fg-subtle)` placeholder
    - Subject field (above body, smaller): Geist 13px input, hairline-bordered, label "Subject"
    - Save edits button: appears when subject or body has unsaved changes — `primary` sm, right-aligned, 8px below fields

## Typography

| Role | Family | Size | Weight | Line Height |
|------|--------|------|--------|-------------|
| Body / prose | Geist (sans) | 14px (0.875rem) | 400 | 1.6 |
| UI label / metadata | Geist (sans) | 13px (0.8125rem) | 400 | 1.4 |
| Message subject (list) | Geist (sans) | 13px (0.8125rem) | 400 | 1.3 |
| Candidate name (list) | Geist (sans) | 14px (0.875rem) | 600 | 1.3 |
| Detail subject / panel header | Fraunces (display) | 16px (1rem) | 600 | 1.25 |
| Folder sidebar heading | Fraunces (display) | 14px (0.875rem) | 600 | 1.2 |

Source: tokens.css type scale + existing route patterns (shortlists/list.tsx, chat.tsx).

Constraints:
- Exactly 2 weights in use per family: Geist uses 400 + 600. Fraunces uses 600 only.
- `tabular-nums` applied to all count badges and timestamps.
- No italic in this phase (editorial italic reserved for chat turn questions).

## Compose Modal Contract

Trigger: "+ New message" button in folder sidebar, or "Draft outreach" CTA from Scoring results sticky bar (deep link).

Modal size: 560px wide, auto-height up to 80vh, `var(--radius-lg)` corners, `var(--shadow-lg)`.

**Fields (top to bottom):**
1. Candidate selector — Geist 13px label "Candidate", Radix Select combobox with search (lists from `GET /upload/` — shows `candidate_full_name` or fallback filename). Required.
2. Content source toggle — two-button toggle group: "AI Draft" | "Template". Default: "AI Draft". Uses `secondary`/`primary` button variant swap to indicate active. No external state needed — local `useState`.
3. Subject — text input, label "Subject", hairline border, Geist 13px, 255-char max, required. Inline validation: red border + "Subject is required" below if empty on blur.
4. Body — textarea, label "Body", hairline border, Geist 14px, auto-expand (min 120px, max 300px), required. Inline validation: red border + "Body is required" if empty on blur.

**Footer:**
- Discard draft: `ghost` sm, label "Discard draft", closes modal, no confirmation if fields are empty; warns "Discard draft?" via inline text (not a nested modal) if subject or body has content.
- Save: `primary` sm, disabled until candidate + subject + body are non-empty, calls `POST /api/v1/outreach/`. On 201: close modal, toast "Message saved to drafts", invalidate outreach query. On 404 (candidate not found): inline error below candidate selector. On network/500: toast error.

## URL Persistence Contract

Route: `/outreach`

Query params persisted to URL (React Router v7 `useSearchParams`):

| Param | Values | Effect |
|-------|--------|--------|
| `folder` | `all` \| `not_sent` \| `sent` \| `failed` | Sets active folder + `sent_status` filter on API call |
| `candidate` | UUID or omit | Filters message list by `candidate_profile_id` |
| `message` | UUID or omit | Opens that message in detail panel on load |

Default: `folder=all`, no candidate filter, no message selected.

Changing the folder via sidebar click updates `?folder=` in URL without full reload (React Router `navigate` with `replace: true`). Selecting a message updates `?message=`. Both filters survive page refresh.

## Interaction States

### Message list row

| State | Visual |
|-------|--------|
| Default | No fill, `border-b border-hairline` |
| Hover | `bg-[var(--hairline)]` (120ms ease-out) |
| Selected | `bg-[var(--hairline-strong)]`, 3px `var(--accent)` left border |
| Loading (skeleton) | Shimmer animation 1.5s loop |

### "Mark as sent" button

- Visible: when `sent_status === "not_sent"` or `"failed"`
- Hidden: when `sent_status === "sent"`
- Loading: disabled + spinner icon while PATCH is in-flight
- On success: badge flips to `success`, message moves out of "Not sent" folder (invalidate list query), toast "Message marked as sent"

### Delete action

- Button: `danger` sm in detail panel header
- Confirmation: inline below the button (not a modal) — small warning text "Delete this message?" + "Confirm" (`danger` sm) + "Cancel" (`ghost` sm) appearing in a 200ms slide-down. No separate confirmation modal (message delete is low-stakes).
- On 204: remove from list (optimistic update via `queryClient.setQueryData`), navigate to empty detail panel, toast "Message deleted"

## Accessibility Contract

- Folder sidebar nav items: `role="listitem"` inside `role="list"`, active item has `aria-current="page"`
- Message list rows: `role="button"` or `<button>` wrapper, `aria-selected` on active row
- Compose modal: `role="dialog"`, `aria-labelledby` pointing to modal title "New outreach message", focus trap on open, Esc closes
- StatusBadge dot: `aria-hidden="true"` (already implemented in badge.tsx)
- "Mark as sent" and "Delete" buttons: explicit `aria-label` in case icon-only states appear
- Relative timestamps: wrapped in `<time dateTime={isoString}>` with Tooltip showing full UTC
- Skip link: not required (AppShell already handles keyboard nav)

## Error Handling Map (Phase 10)

| HTTP Status | Trigger | UI Behaviour |
|-------------|---------|--------------|
| 404 (GET list) | `candidate_profile_id` not found | EmptyState "No messages for this candidate" |
| 404 (GET single) | `message_id` gone | Detail panel shows EmptyState — Heading: "Message not found" / Body: "This message may have been deleted. Return to the message list." + toast "This message no longer exists" |
| 404 (POST) | Candidate not found | Inline error below candidate selector in compose modal |
| 404 (PATCH) | Message deleted elsewhere | Toast "Message no longer exists" + close detail panel |
| 204 (DELETE) | Success | Optimistic remove + toast |
| 500 | Any | Toast "Something went wrong. Please try again." |
